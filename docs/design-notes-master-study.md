## 0. 最大の学び — 実寸換算を先にやる

モバイル UI は直感より小さい。採寸せずに作ると**全要素を約1.4〜1.6倍過大**に作る
(今回のスタディで実測)。スクショからの換算式:

```
論理px = スクショ表示px × (402 / スクショ表示幅)
(iPhone実機スクショ: 論理幅402pt・@3x。表示920px なら ×0.437)
```

検証はスクリーンショットの目視ではなく **getBoundingClientRect の実測**を根拠にする
(検証ペインの表示倍率は揺れる)。

## 3. 面の作り(N2 との構造差 — 参考知見)

- **ボーダーほぼ無し。明度3段+大きめ radius で面を分ける**:
  bg #0A0A0B → card #131315 → tile #1B1B1E(+ボタン #2A2A2E)、カード radius 16〜20
- 純白は CTA とバッジのみに絞って反転を効かせる(**白面積の希少化** — N2 の金運用と同型の設計思想)
- テキスト階層は 3値: #EDEDEF / #A3A3AA / #8A8A92
- ※ N2 は「1px line+明度差」文法・radius 13/10/6 を維持する(T13 制約)。ここで
  持ち帰るのは「radius と明度段差のスケール感」「白(=N2では金)の希少運用」のみ

## 4. 余白・グリッド

- ページ左右パディング **14**
- セクション上余白 30〜38 / 見出し下 12〜14
- 2列グリッド gap **11** / カード内パディング 12前後
- 横スクロール列 gap 14 / カード min-width 198(画面の約49% — 次カードを覗かせる)

## 5. 構図

- ヒーロー: ビジュアル高 245(カード高の約55%)。被写体をカード端で軽く切る
  (overflow hidden)ことで密度を出す。中央被写体:脇=129:92、脇の覗き幅 約26
- カテゴリカード: ビジュアル高 210、スラブ幅≒カード幅84%、パックが下半分に重なる
- ステージカード: 台座径≒カード幅60%、被写体は上 18px から
